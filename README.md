# UP02.02 — экспорт отчётов в PDF и Excel

Приложение Windows на C#. Версия 0.1.0 поддерживает шаблоны, потоковую обработку больших CSV, оформление Excel и автоматические тесты.

## Ветки разработки

`dev-code` содержит исходный код приложения, `dev-tests` — отдельный тестовый проект. Ветка `codex/ci-release-v0.1.0` объединяет приложение и тесты для общей проверки и подготовки релиза.

Для сборки и запуска тестов используйте ветку, содержащую одновременно `src` и `tests`.

## Готовое приложение

В [Releases](https://github.com/GrowlHeart/MDK02.02/releases) скачайте UP02.02.exe для Windows x64. Устанавливать .NET для готового EXE не требуется.

## Как пользоваться

1. Измените исходные строки в таблице или добавьте свои.
2. Справа задайте название, колонтитулы, шрифт, его размер, цвет заголовка и число знаков после запятой.
3. По необходимости включите чередование фона строк и график Excel.
4. Нажмите Excel или PDF и укажите место сохранения.
5. Кнопки «Сохранить шаблон» и «Загрузить шаблон» сохраняют оформление в JSON.

Excel содержит числовые ячейки, заголовок, итог, денежный формат, закреплённые заголовки, фильтр и печатные колонтитулы с номером страницы. Колонтитулы видны в режиме разметки страницы или при печати. График находится на отдельном листе «График» и показывает суммы первых 20 позиций. Его можно отключить.

PDF содержит повторяющийся заголовок таблицы, колонтитулы и номер страницы. Длинные названия переносятся на несколько строк. Очень большие денежные значения печатаются уменьшенным шрифтом, сохраняя все цифры.

## Большие наборы данных

Нажмите «Пример 100000 строк», чтобы создать пример CSV, или откройте свой CSV. Нужны UTF-8 и разделитель ;. Первая строка должна содержать точные названия столбцов:

```csv
Наименование;Количество;Цена
Бумага А4;5;350.00
"Папка; архив";3;120,50
```

Допустимы десятичная точка и запятая, а для названий с разделителем — кавычки. Название содержит 1–200 символов, количество — целое число от 0 до 1000000, цена — от 0 до 1000000000000. У пустого отчёта экспорт отклоняется.

При открытии CSV в окне показаны только первые 100 строк для просмотра. Экспорт читает весь файл, последовательно по одной строке. Редактировать предварительный просмотр нельзя; кнопка «К таблице» возвращает ручной ввод.

Excel записывается через OpenXmlWriter, PDF рисуется постранично через SkiaSharp. В программе нет списка со всеми строками CSV. В памяти остаются текущая строка, небольшое состояние генератора и первые 20 строк для графика; библиотеки также используют свою служебную память. Большой PDF занимает много страниц, поэтому для обработки данных удобнее XLSX. На листе Excel помещается до 1048572 строк данных с учётом заголовков и итога; при превышении выводится ошибка.

Экспорт работает в фоне. Доступны счётчик строк и отмена. Результат сначала записывается во временный файл: при ошибке или отмене старый файл отчёта сохраняется, временный файл удаляется.

## Где находится код

| Файл | Назначение |
| --- | --- |
| src/App/Program.cs | Окно, кнопки, выбор файлов и запуск экспорта |
| src/Core/Models.cs | Строка отчёта, шаблон JSON, чтение CSV и безопасное сохранение |
| src/Core/ExcelReport.cs | Построчная запись XLSX, стили, колонтитулы и график |
| src/Core/PdfReport.cs | Постраничная запись PDF |

Перед функциями есть короткие комментарии об их назначении. Основной путь: кнопка Export → ReportExporter.Export → ExcelReport.Write или PdfReport.Write.

IEnumerable<ReportRow> передаёт строки по очереди. CancellationToken сообщает, что пользователь нажал отмену. OpenXmlWriter записывает элементы XLSX сразу, не собирая таблицу целиком. График хранится в XLSX как отдельная XML-часть, связанная с диапазонами исходного листа.

## Сборка и тесты

Для исходного кода нужны Windows и .NET 8 SDK:

```powershell
dotnet build ReportExport.csproj -c Release
dotnet run --project ReportExport.csproj
```

Тестовый проект ссылается на `src/Core/ReportExport.Core.csproj`. В общей ветке CI оба проекта уже доступны; в отдельной `dev-tests` исходников приложения нет.

```powershell
dotnet test tests/ReportExport.Tests.csproj -c Release --collect:"XPlat Code Coverage" --results-directory TestResults
```

Шесть тестов проверяют расчёт с decimal, точность числового формата, оформление XLSX, ссылки графика, однократное чтение источника из 100000 строк и создание PDF. XLSX дополнительно проверяется валидатором Open XML. Отчёт покрытия сохраняется в TestResults. Эти проверки не заменяют ручную проверку интерфейса и печати в Excel.

## Автоматическая проверка CI

GitHub Actions запускает `.github/workflows/ci.yml` при push и открытии или обновлении Pull Request. На Windows с .NET 8 выполняются восстановление зависимостей, проверка форматирования C#, сборка приложения и тестов с ошибкой при предупреждениях, запуск тестов с покрытием и сборка автономного EXE.

На странице запуска Actions доступны артефакты `test-results-and-coverage` (TRX и Cobertura) и `UP02.02-windows-x64` (EXE). Результаты тестов сохраняются и при ошибке последующих шагов. EXE создаётся только после успешных проверок. CI не публикует релиз автоматически.

Локальная проверка форматирования:

```powershell
dotnet format whitespace ReportExport.csproj --verify-no-changes
dotnet format whitespace tests/ReportExport.Tests.csproj --verify-no-changes
```

Для запрета слияния при неуспешных проверках в защите `main` нужно выбрать обязательный статус `Build, format and test`.

Сборка одного автономного EXE:

```powershell
dotnet publish ReportExport.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None -p:DebugSymbols=false -o release
```

Основные библиотеки: Open XML SDK для XLSX, SkiaSharp для PDF, xUnit для тестов. Права доступа и аккаунты пользователей приложению не требуются.
