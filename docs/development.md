# Порядок разработки

Общий проект находится в `main`. Приложение и тесты первоначально готовились в `dev-code` и `dev-tests`, затем были объединены через Pull Request. Дальнейшие изменения выполняются в отдельных ветках от актуального `main`.

## Задача и ветка

1. Создать Issue, указать результат и ответственного.
2. Назначить milestone и добавить карточку на Kanban.
3. Создать ветку `feature/НОМЕР-ISSUE-краткое-название`.
4. После реализации открыть PR в `main` и указать `Closes #НОМЕР`.
5. Получить review, исправить замечания и дождаться успешного CI.
6. Выполнить QA и объединить PR, когда выполнены требования защиты ветки.

Колонки Kanban по заданию: Backlog, Ready, In Progress, Code Review, QA, Done. Карточки перемещаются по фактическому состоянию задачи. [Milestone завершения практики](https://github.com/GrowlHeart/MDK02.02/milestone/1) объединяет завершающие работы.

## Защита main

Для слияния требуется PR, минимум один approve участника с правом записи и успешная проверка `Build, format and test`. Ветка PR должна быть актуальна относительно `main`. После новых изменений старый approve может быть сброшен. Защита действует и для администратора; force push и удаление `main` запрещены.

## Pre-commit

В [`.githooks`](../.githooks) находится проверка форматирования приложения и тестов. Она не исправляет файлы автоматически: неправильное оформление останавливает коммит. При конкретном временном сбое поиска .NET CLI предусмотрен один повтор; остальные ошибки не игнорируются.

Каждый участник подключает hook в своей локальной копии:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install-hooks.ps1
dotnet restore ReportExport.csproj
dotnet restore tests/ReportExport.Tests.csproj
```

При необходимости исправить форматирование:

```powershell
dotnet format whitespace ReportExport.csproj --no-restore
dotnet format whitespace tests/ReportExport.Tests.csproj --no-restore
```

При проверке настройки настоящий коммит с тремя лишними пробелами в начале `Program.cs` был заблокирован. После восстановления файла обычный коммит прошёл проверку. Hook подключается локально и сам по себе не включается у другого участника после скачивания репозитория.

## CI

[Workflow](../.github/workflows/ci.yml) запускается при push и событиях PR. На Windows с .NET 8 выполняются восстановление зависимостей, форматирование, сборка приложения и тестов, тесты с покрытием и автономная сборка EXE. Предупреждения при сборке считаются ошибками.

Артефакт `test-results-and-coverage` содержит TRX и Cobertura XML, `UP02.02-windows-x64` — EXE. Они хранятся 14 дней. В документации сохранена копия отчёта одного успешного запуска.

Workflow учитывает поэтапное объединение проекта: если проектов ещё нет, он сообщает, что сборка и тесты не выполнялись. При наличии приложения без тестового проекта выполняет проверки приложения. Тесты без исходников Core завершаются ошибкой. В текущем `main` присутствуют оба проекта.
